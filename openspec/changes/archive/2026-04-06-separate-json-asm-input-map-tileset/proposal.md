## Why

The current extract-map-tileset workflow still depends on loading a PNG tileset image together with the JSON map. This makes preview and validation dependent on image assets and does not reflect the compacted tile set generated by extract-tiles when excluded tiles are removed.

To keep map data aligned with compacted tile indexes, extract-map-tileset should load tile bitmaps and attributes directly from the ASM output generated by extract-tiles.

## What Changes

- Replace the combined JSON+PNG loading flow with two explicit inputs: Tiled JSON map file and ASM tileset data file.
- Parse ASM `defb` tile bytes and optional `_tiles_attributes` section into per-tile bitmap data.
- Render map preview from parsed ASM tile data instead of PNG image sampling.
- Validate that maximum tile index used by the map does not exceed parsed ASM tile count.
- Update user-facing labels and errors for the new JSON+ASM source contract.

## Capabilities

### New Capabilities

- `map-tileset-json-asm-input`: Accept map JSON and ASM tile data as independent inputs for extract-map-tileset.
- `map-tileset-asm-preview`: Build map preview from ASM bitmap/attribute data without requiring PNG tileset loading.

### Modified Capabilities

- `map-tileset-json-input`: Extend JSON-based map extraction flow with ASM-backed tile source validation.

## Non-goals

- Supporting legacy PNG-based preview in this flow.
- Supporting arbitrary hand-written ASM formats beyond extract-tiles compatible `defb` output.
- Changing map output code generation formats (C/ASM) beyond source ingestion and preview behavior.

## Impact

- Affected area: web-client extract-map-tileset composable, preview component, and shared image helper rendering path.
- Introduces ASM parsing logic in extract-map-tileset module.
- Adds localized messages for ASM-related validation and format errors.
