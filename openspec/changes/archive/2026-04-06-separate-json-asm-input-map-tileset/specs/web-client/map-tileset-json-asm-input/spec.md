## ADDED Requirements

### Requirement: System requires separate JSON and ASM sources for map tileset extraction

The system SHALL require two independent source files in extract-map-tileset: a Tiled-exported JSON map file and an ASM tile-data file generated by extract-tiles.

#### Scenario: Both source files are valid

- **GIVEN** the user provides a valid JSON map file and a valid ASM tile-data file
- **WHEN** both files are loaded
- **THEN** the system MUST mark extraction as ready and allow preview/extraction actions

#### Scenario: Missing ASM source blocks readiness

- **GIVEN** the user provides only a valid JSON map file
- **WHEN** ASM source is not provided
- **THEN** the system MUST NOT enable extraction

### Requirement: System parses extract-tiles ASM tile data for preview

The system SHALL parse ASM `defb` bytes into per-tile bitmap data and SHOULD parse optional tile attribute bytes for colorized preview.

#### Scenario: ASM with tile data and attributes

- **GIVEN** an ASM file containing tile bitmap `defb` bytes and `_tiles_attributes` data
- **WHEN** the system parses the ASM source
- **THEN** the preview renderer MUST use parsed bitmaps and attribute bytes

#### Scenario: ASM without attributes

- **GIVEN** an ASM file containing tile bitmap data but no attributes section
- **WHEN** the system renders preview
- **THEN** the system MUST render using fallback colors without failing extraction

### Requirement: System validates map indexes against ASM tile count

The system SHALL reject source combinations where map tile indexes exceed available decoded ASM tiles.

#### Scenario: Map references unavailable tile index

- **GIVEN** parsed map data has max tile index `N`
- **AND** ASM decoding provides fewer than `N` tiles
- **WHEN** validation runs
- **THEN** the system MUST display a blocking validation error and MUST NOT enable extraction

### Requirement: System reports unsupported ASM formats clearly

The system SHALL provide actionable errors for unsupported ASM source formats.

#### Scenario: Invalid ASM token syntax

- **GIVEN** the ASM file includes non-supported byte tokens in `defb` entries
- **WHEN** parser processes file
- **THEN** the system MUST reject the source and show an ASM format/token error

## MODIFIED Requirements

### Requirement: JSON map ingestion remains strict and fail-fast

The system SHALL continue strict JSON schema validation for map input before any extraction state is applied.

#### Scenario: JSON valid but ASM invalid

- **GIVEN** a valid JSON map file and an invalid ASM file
- **WHEN** sources are validated
- **THEN** JSON state MAY be loaded but extraction MUST remain disabled until ASM becomes valid
