# Project Bootstrap Design — zx-ide

## Architecture Decisions

### AD-1: Hybrid persistence (OpenSpec + Engram)

**Decision**: Use OpenSpec as the canonical artifact store and Engram as the cross-session memory/search layer.

**Rationale**: The project already had OpenSpec artifacts (`openspec/changes/unify-sprites-editor/`, `openspec/specs/*`) when this init ran. The user clarified that OpenSpec is the team-visible store, while Engram is useful for cross-session recall. The `unify-ai-governance` change uses Engram-only because it is a refactor with no lasting spec value — that is preserved separately and must not be touched.

**Alternatives considered**:
- OpenSpec-only: Rejected because Engram provides valuable cross-session memory that survives compactions.
- Engram-only: Rejected because OpenSpec is required for team sharing and code review of SDD artifacts.

### AD-2: Strict TDD disabled for vscode-extension, enabled for web-client

**Decision**: `strict_tdd: false` for `projects/vscode-extension` (uses `@vscode/test-electron` for integration tests only, no unit runner). `strict_tdd: true` for `projects/web-client` (Vitest detected with `npm run test`). Not applicable for `projects/cli` (no test runner).

**Rationale**: VS Code extension integration tests require a full VS Code environment and are not suitable for TDD at the unit level. The web-client has Vitest with proper unit test support. CLI has no test infrastructure.

### AD-3: Skill registry at `.atl/skill-registry.md`

**Decision**: The registry already exists at `.atl/skill-registry.md` and was updated as part of the `unify-ai-governance` change. It includes both user-level skills (from `~/.config/opencode/skills/`) and the project-level `vue-best-practices` skill.

**Rationale**: Having a registry avoids agents having to search skill paths at runtime. The `.atl/` location follows the opencode convention for agent tooling.

### AD-4: Per-project instructions in `.ai/instructions/`

**Decision**: Each sub-project has its own instruction file (`.ai/instructions/{cli,vscode-extension,web-client}.md`) created during the `unify-ai-governance` change. These are the canonical conventions for agents working in each sub-project.

**Rationale**: Consolidating project-specific conventions into per-project files keeps AGENTS.md lean while ensuring agents get relevant context before editing code.

## OpenSpec Layout

```
openspec/
├── config.yaml                  ← generated by sdd-init; carries project context
├── config.yaml_                 ← user backup, left untouched (legacy)
├── specs/
│   ├── binary-input-panel/
│   ├── binary-matrix-rotation/
│   ├── create-sprites/
│   ├── create-tiles/
│   ├── shared-code-generators/
│   ├── sprites-creator-section/
│   └── project-bootstrap/       ← NEW: this init
│       ├── spec.md
│       └── design.md
└── changes/
    ├── archive/                 ← completed changes
    └── unify-sprites-editor/    ← active/completed change
```
